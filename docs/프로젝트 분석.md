# 프로젝트 분석 (React Cinema Archive)

## 1. 프로젝트 개요
- 본 프로젝트는 빠르고 가벼운 번들러인 **Vite**를 기반으로 구성된 **순수 리액트(React 19) 싱글 페이지 애플리케이션(SPA)** 입니다.
- 기존의 클라우드 플랫폼 특화/풀스택(Express + React) 혼합 보일러플레이트 구조에서 백엔드 영역을 덜어내고, 독립적인 프론트엔드 전용 아키텍처로 재구성되었습니다.

## 2. 주요 기술 스택
- **코어 프레임워크:** React 19, Vite
- **패키지 매니저:** pnpm
- **스타일링:** Tailwind CSS v4, DM Sans / Libre Baskerville / DM Mono 웹폰트, 순수 CSS 모션
- **UI 생태계:** Radix UI (`@radix-ui/react-slot`, `@radix-ui/react-tooltip`), Lucide React (SVG 아이콘), Sonner (토스트 알림)
- **클라이언트 라우팅:** wouter (초경량 선언적 SPA 라우터)

## 3. 디렉토리 구조 (주요 폴더 및 파일)
- **`src/`**: 프론트엔드 핵심 소스 코드.
  - **`components/`**: 영화 카드(`MovieCard`), 아카이브 목록(`MovieList`), 상세 모달(`MovieModal`), 헤더(`Header`), 히어로(`Hero`), 에러 경계(`ErrorBoundary`) 등 UI 컴포넌트 및 필수 위젯 (`ui/`)
  - **`contexts/`**: 다크/라이트 모드 테마 컨텍스트 (`ThemeContext.tsx`)
  - **`data/`**: 아카이브 영화 큐레이션 데이터셋 (`movies.ts`)
  - **`pages/`**: 페이지 단위 컴포넌트 (`Home.tsx`, `NotFound.tsx`)
  - **`App.tsx`**: 최상위 라우터 및 전역 Provider (`ErrorBoundary`, `ThemeProvider`, `TooltipProvider`, `Toaster`, `wouter`)
  - **`main.tsx`**: React 19 `StrictMode` 진입점
- **`public/`**: 빌드 시 루트 경로로 복사되는 정적 리소스 폴더 (`favicon.svg`).
- **`docs/`**: 프로젝트 분석 및 가이드 문서 보관.
- **`dist/`**: 프로덕션 빌드 결과물 (`index.html` 0.63KB, 경량 CSS 번들 32.77KB, `favicon.svg`).
- **`vite.config.ts`**: 순수 React 19 + Tailwind CSS v4 번들러 설정.
- **`tsconfig.json`**: TypeScript 컴파일러 설정 (Vite + React 전용 표준 구성).

## 4. 프로젝트 실행 및 종료 가이드

본 프로젝트는 `pnpm`을 통해 패키지 관리 및 스크립트를 실행합니다. 

### 4.1. 개발 서버 실행 (Development Mode)
코드를 수정하면 즉시 브라우저에 반영되는(HMR) 개발 전용 서버를 엽니다.
- **시작 방법:** 터미널에서 `pnpm run dev` 명령어 입력
- **접속 주소:** `http://localhost:3000` (포트가 사용 중일 경우 다음 가용 포트로 자동 할당됨)
- **종료 방법:** 
  1. 개발 서버가 구동 중인 터미널 창을 활성화합니다.
  2. 키보드에서 `Ctrl + C` 를 누릅니다.
  3. *(윈도우의 경우)* "일괄 작업을 끝내시겠습니까 (Y/N)?" 프롬프트가 나오면 `Y`를 누른 뒤 `Enter`를 쳐서 서버 프로세스를 완전히 종료합니다.

### 4.2. 타입 및 문법 검사 (Type Checking)
- **검사 방법:** 터미널에서 `pnpm run check` 입력
- 런타임 실행 없이 순수하게 TypeScript 코드 상의 에러 여부(`tsc --noEmit`)만을 검사하여 출력합니다. 배포 전 코드의 무결성을 점검할 때 유용합니다.

### 4.3. 프로덕션 빌드 (Production Build)
실제 운영 환경에 배포하기 위해 코드 난독화/최적화 등을 거친 정적 파일을 생성합니다.
- **빌드 방법:** 터미널에서 `pnpm run build` 명령어 입력
- **결과물:** 최상위 디렉토리에 `dist/` 폴더가 생성되며, 실제 웹 서버(Nginx, Vercel, AWS S3 등)에는 이 폴더의 내용을 배포합니다.

### 4.4. 빌드 결과물 로컬 확인 (Preview)
배포 전에 `dist/` 폴더에 빌드된 프로덕션 결과물이 정상적으로 작동하는지 로컬에서 미리 테스트합니다.
- **실행 방법:** 빌드를 마친 후, 터미널에 `pnpm run preview` 명령어 입력
- **접속 주소:** 터미널에 출력되는 로컬 주소 (일반적으로 `http://localhost:4173`)
- **종료 방법:** 개발 서버와 마찬가지로 터미널에서 `Ctrl + C` 키를 입력하여 종료합니다.

## 5. 순수 프론트엔드 표준화 및 최적화 작업 요약
과거 클라우드 플랫폼(Manus) 전용 보일러플레이트에서 발생했던 잔재들을 모두 제거하고 표준 순수 React 프로젝트로 정제했습니다:
1. **플랫폼 런타임 및 정적 에셋 제거**: 빌드 산출물에 350KB 분량의 플랫폼 런타임을 강제 주입하던 `vite-plugin-manus-runtime`, `@builder.io/vite-plugin-jsx-loc`과 함께 `public/__manus__` 정적 파일, `patches/` 디렉터리 및 불필요한 설정 파일을 완전히 삭제.
2. **의존성 다이어트 (376개 패키지 제거)**: 실제 서비스에 사용되지 않던 대규모 패키지(`axios`, `recharts`, `zod`, `react-hook-form`, `streamdown`, `vaul`, `cmdk`, `react-day-picker`, `framer-motion`, 20여 종의 `@radix-ui/*` 패키지)를 제거하여 node_modules 및 빌드 번들 용량을 극적으로 경량화 (CSS 번들 93KB → 32.77KB).
3. **UI 및 테마 시스템 통합**: `sonner.tsx`를 프로젝트 자체 `ThemeContext`와 일원화하고 `next-themes` 의존성을 제거, `src/index.css`에 `--background`, `--foreground`, `--popover`, `--border`, `--destructive`, `--accent` 등의 UI 테마 토큰을 매핑하여 테마 안정성 확보.
4. **브라우저 완성도 및 디자인 일관성**: 브라우저 404 에러를 유발하던 파비콘 부재 문제를 해결하기 위해 `public/favicon.svg`를 제작 및 연결하고, 템플릿 기본 스타일이었던 `NotFound.tsx` 페이지를 Cinema Archive 고유의 아카이브 감성(Serif/Mono 타이포, 웜톤 테마)으로 완벽히 통일.
5. **리액트 아키텍처 완성**: `main.tsx`에 `React.StrictMode` 적용, `App.tsx`에 `ErrorBoundary`, `ThemeProvider`, `TooltipProvider`, `Toaster`, `wouter` 라우팅(`Home`, `NotFound`)을 온전히 연결하여 안정적인 SPA 구조 확립.
